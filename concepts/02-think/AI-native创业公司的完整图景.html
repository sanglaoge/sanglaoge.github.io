AI-native创业公司的完整图景

稳定 建条 2026-06-23 下次复核 2026-11-18

AI-native 创业公司不是"装了 AI 的传统公司"，而是一个四层叠加的系统：方向由 Sam Altman Test 筛选，组织形态由 AI Loop 重塑，技术由循环工程驱动，第一步是隐性知识显式化。

四层模型总览

一层 做什么方向？——Sam Altman Test（AI-native 三法则）
"模型更强时，你的服务是变强还是被商品化？" 过滤器
二层 公司长什么样？——Tom Blomfield 的 AI Loop 五层架构
传感器→规则→工具→质检→学习，业务自动闭环 组织形态
三层 技术怎么实现？——循环工程
触发器+隔离+上下文+工具+验证器+磁盘状态 引擎
四层 第一步干什么？——隐性知识显式化
"没有被记录的业务，就没有发生在你的 AI 里" 燃料

四层自上而下是过滤→塑形→实现→供养；第四层的结果反向喂养第二、三层——没有它，Loop 没东西可转

第一层：做什么方向（Sam Altman Test）

核心问题模型越强，你越强还是被商品化？

三个法则回答创业公司的"做什么 / 不做什么 / 怎么赚钱"（详细框架见灰字条目 AI-native服务公司三法则，未建页面）：

法则回答的问题大白话
Sam Altman Test做什么模型越强你越强，不是"也会用 AI"就安全
Early Demand Trap不做什么别过早签太多定制客户，否则变成"有 AI 的外包"
AI Operating Leverage怎么赚钱产品越建成本越低，不靠加人扩大产能

这一层给你的是一个过滤器——拿一个新业务 idea 过来，三秒钟判断"这个方向值不值得做 AI-native"。不做什么，比做什么更重要。

第二层：公司长什么样（AI Loop 五层架构）

Tom Blomfield（YC General Partner）

"烧 token，不要烧 headcount。中层管理结束了。"YC Batch Talk：How to Build a Self-Improving Company with AI

把一个能自我闭环的业务循环拆成五层：

层名称干什么举例
1传感器 Sensor让系统看见输入客户邮件、投诉工单、退订数据、产品埋点
2规则 Policy定边界哪些 AI 自动做、哪些须人批准、哪些必须记录
3工具 Tool让 AI 能动手查 DB、调 API、读日历、写代码
4质检 Quality Gate把关eval 检查、规则校验、安全过滤、高风险人工审核
5学习 Learning失败写回把失败案例喂回规则库，系统越跑越聪明

三个关键洞察：

  • 烧 token 不烧 headcount：YC 最新 Demo Day 公司，每人产出收入比 18 个月前高约 5 倍。扩张的瓶颈不是招不到人，是 token 用量（Tokenmaxxing 的公司经营层面）
  • 中层管理终结：信息收集、状态同步、任务拆解这些"人肉传声筒"工作正被 AI Loop 接管；留下的不是"盯人"，是"设计系统边界"
  • 软件变轻，上下文变重：内部仪表盘变成可抛弃品（Codex 能 one-shot 生成），真正的资产是业务上下文和 skills（上下文工程）
实战故事 · Laurel 的公司 OS 落地

Laurel CPO Jiaona Zhang（前 Airbnb / Dropbox / Webflow PM）用 Claude Code 把五层架构落地成"公司 OS"：公司 OS 不一定一开始就是 OS，它从第一个自动化的小工作流开始。

Tom 的理论层Laurel 的实战落地
工作地图化公司工作按职能拆成 GitHub 目录，每个文件夹是可被 Claude 调用的 skill
从小自动化开始先解决一个天天重复的烦人动作（如 Slack 里反复问产品需求背景）
Playbook 拆成 skill50 页 GTM playbook 把可重复部分拆成 agent，需要判断和客户关系的步骤留给人
入口在 Slack / 邮箱摩擦会杀死习惯：销售在 Slack 接活，按钮就在 Slack
AI Ops 要全职"每个人的责任"就是"没人的责任"，要配全职岗位写进 charter
Captain model谁能解决最难部分谁 captain，不按职能分

"很多时候，当你说它是每个人的责任，它最后就成了没有人的责任。"

第三层：技术怎么实现（循环工程）

核心逻辑别手动写提示词，写一个会自动循环的程序

Tom 的五层 AI Loop 是业务架构，循环工程是工程实现，两者是上下游关系：

Tom 的业务层循环工程的工程实现
传感器触发器（webhook / 定时任务 / 文件变更）
规则写下来的上下文（CLAUDE.md / Skills / Memory）
工具接入工具（MCP / API / Skill）
质检独立验证器（第二个 AI 检查，不能自己给自己打分）
学习磁盘状态（记录进度、规则库更新）
成本认知翻转：成本不是"哪个模型 × 多少 token"，而是"循环转了几圈"。便宜模型循环翻倍反而更贵——先收紧验证器，弱验证器是最贵的 bug。

第四层：第一步干什么（隐性知识显式化）

核心行动"如果没有被记录，就没有发生在你的智能里"——Tom Blomfield

没有记录 → 没有上下文 → AI 读不懂 → Loop 转不起来

理论基础见 隐性知识。公司级别的提取路径四步走：

步骤做什么效果
1记录一切：邮件、Slack、会议录音、客服记录全部入库AI 有东西可以读
2结构化：diarize → 聚合 → 压缩 → 分类把噪音变成可追踪的面包屑
3写成上下文：业务规则变成 Skills、规则文件、工具说明AI 能执行，不只是查询
4接入 Loop：上下文+工具+质检+学习机制连起来系统开始自我改进
实战故事 · YC 的活手册

Harj 用 3 个月约 2000 小时 office hour 录音，重新生成一份 150 页 YC 用户手册——旧手册写于 5-10 年前早已过时。新手册每月更新，公司知识变成"活的大脑"。个人层面用 tacit-mining 技能提取隐性判断，公司层面走上面四步；具体工具见 隐性知识抽取。

清醒话：价值不会自动全归模型公司——"价格和价值会流向稀缺的东西"，模型不稀缺，懂行+信任才稀缺；代码可复制，客户网络复制不走。"一个需求不够大到让全球平台下场，并不妨碍它成为一个人的真实生意。"桑老哥起手式：设计重复活 → 小工具 → 真实用户付费验证。

build 越快，债务越快（实战验证）

AI 加速 building，但没让维护成本消失。Muji（Seede AI co-founder）《AI 创业第一年复盘》的血泪账：

领域demo 阶段产品阶段（真实债务）
支付微信支付跑通付费墙、续费、退款、税务、渠道结算、异常补偿
数据看到点击/注册/付费转化率、流失原因、渠道对比、口径一致性
客服创始人手动回复文档、工单、错误日志、排查路径、30+ 群头
文档写一篇 quickstart功能更新跟不上、API 变了、AI 答案不准
埋点接 GA 看大概命名不统一、新老数据对不上、查询把 DB 搞崩
核心洞察：AI coding 解决 one-time building，没解决 keep it running。护城河不在"生成更多东西"，而在"把生成的东西安全、稳定、长期地变成业务资产"。如果产品能力完全因为模型牛逼而牛逼，那就是模型的功劳。

前提与局限

  • 面向 AI 创业 / 技术团队；"业务上下文变重"的思路对个人同样通用
  • "中层管理终结"消失的是信息搬运层，决策判断仍需人（适用于 50 人+）
  • "记录一切"有隐私红线——客户、员工、情绪场景不能粗暴进数据湖
  • 烧 token 的前提是业务可 AI 化：知识还在人脑里，Loop 就转不起来
  • 四层是理想态，实际可从任一层切入，但长期需补齐才有护城河
