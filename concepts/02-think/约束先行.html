思维模型 · Agent 协作的规矩层

约束先行

稳定 建条 2026-08-03 下次复核 2026-11-18

用好 Agent，最重要的不是 Skills 和 Prompt 技巧，是在让 Agent 干任何事之前，先把规范从上往下定好——没有规矩的地方，不动手。

四层穿透体系

一句话解释：全局规矩 → 项目规矩 → 文件夹规矩，约束从上往下穿透，一层管一层。

约束从上往下穿透，一层管一层——越往上越稳定，越往下越具体

关键数字

80 行以内最好
200 行硬上限
为什么CLAUDE.md 超过 80 行，Claude 开始遗漏内容

两个核心原则

没有规范的工作空间不动手

新项目第一件事：先写 CLAUDE.md，再谈干活。

改规则也要走规则的路

先改文档，再改实践——顺序反了，规矩就失效。

约束先行 = 模拟经营游戏的路网规划。前期花一小时规划主干道，后面省无数小时返工。

长任务四件套 ·核心

下长任务（迁移 / 重构 / 批量改稿 / 资料整理）前，先把四样写进文件再放手：

规则书

先写清哪些照做、哪些重做、依赖啥；拿 3 个样本试航把坑炸出来（试错样本可扔）。

裁判

什么算对先定，并用"故意改坏的版本"测一次——原版过、坏版也过 = 裁判失灵（"能运行"不等于行为一致，太松）。

任务账本

下一步写进文件 / 队列，别只存聊天里——聊天会压缩、会话会换、人会忘。

断点

靠文件接住，不靠人回忆；换个人只看文件就能说出"做完了啥 / 下一步啥 / 卡哪"才算合格。

底线三句：容易忘的交给文件，容易争的交给裁判，最后取舍留给人。重复出错改规则别改结果——经验写回长期规则，才算修到上游。填不出完成标准，先别扩 Agent。这是五要素"合格线"在长任务场景的完整落地版，对应 目标契约与五个闸门 的验收闸门。
