Agent自进化

稳定 建条 2026-08-24 下次复核 2026-11-24

一句话说清楚

Agent 改了自己 ≠ 变强；没见过的任务也变好才算变强；分数上涨要先排除四种假象再高兴。

Agent 用干活攒下的经验反过来修改自己（改提示词、改记忆、改技能、甚至改参数），让它下次干得更好。听起来很美，但「改了」和「变强了」中间隔着三道验证——这篇的贡献就是把这三道验证和其中的坑讲清楚。

三层判定：什么才叫自进化

层判定健身比喻
① 自进化事件经验被写回（存进 memory / 生成 skill），跨任务还在用记了训练笔记
② 有效自进化没见过的同类任务也变好了陌生考试也提分
③ 可靠自进化没把原来会的能力搞坏，出了问题能撤销回滚体检没毛病，随时能停药

关键分界：任务内的反思（干完一件事总结两句）只是信号——没有写回、下次不在，就什么都不是。

最毒的坑：分数上涨 ≠ 能力上涨 ·核心

一次测试变好了，先别庆祝，四种替代解释逐个排除：

  • 多抽了几次卡——抽 10 次选最好那张，不等于画功变强（Pass@K，采样涨分）。桑老哥做 AI 视频天天遇：抽 3 次卡选最好是「选出来的」，不是能力。
  • 背下了考题——只对这套测试有效，换套题就露馅（Benchmark 过拟合）。
  • 讨好评分员——钻评分规则漏洞刷高分（Reward Hacking，详见 图谱工程 自改进循环的「作弊三招」）。
  • 环境帮忙/人工接管——看起来它做成了，其实是人兜的底。

一句话带走：三问打分卡

看到 Agent「越用越聪明」，先问三句
1
写回了吗？
经验存进 memory / skill，跨任务还在用——没写回就只是任务内反思
2
陌生任务也变好了吗？
held-out 验证：没见过的同类题也提分，才是迁移增益
3
谁批的准？
评估、批准、撤销的权力必须在独立手里——不能自己给自己打分

能改自己哪些部位：从外到内

模型升级不是唯一路径，Agent 身上每层都能改：

层比喻铁柱的实物
Prompt改便签单次对话里的指令
Context桌上摊什么资料塞进上下文的文件
Memory改笔记本桑老哥说「记住这个」→ 写 memory
Tool / Skill改工具箱「存成 skill」→ Skill 层
Workflow改流程图编排 / subagent 流程
Harness改车间调度规则改 CLAUDE.md / hooks
模型参数改大脑本身换模型、微调

原则一句话：最小够用——出问题先找根因在哪层，用最小、最浅、最容易撤回的那层去修。事实缺了补 Context，接口错了修 Skill，流程乱了改 Workflow。别动不动就指望「模型再聪明一点」。

裁判和运动员必须分开（控制面分离）

运动员（生成）

Agent 可以提议任何修改：改提示词、改记忆、改技能——提议权全给它。

裁判（评估·批准·撤销）

必须握在独立手里。既当运动员又当裁判，它完全可以把评分标准改得让自己永远满分。

这是 出稿评审分离法 的工程版，也和 图谱工程 自改进循环的命根子规则同源：别让提出方案的人移动标准线。

在铁柱这儿的落地：桑老哥就是独立裁判——铁柱说「做完了」不算数，你看结果点头才算。

小白说法 ↔ 专业术语

小白说法专业术语
改自己身上某个部位更新对象（Prompt/Memory/Skill/Harness/参数，合称脚手架 Σ）
没见过的题也做对了迁移增益（Held-out test 验证）
多抽几次卡挑最好的Pass@K（采样次数带来的涨分）
钻评分漏洞刷高分Reward Hacking（奖励投机）
提议的和批准的分开控制面分离（生成/评估/发布三权分立）
用最小改动修根因最小够用更新原则（minimal-sufficient update）

轻记：Warp 自我进化 Agent（2026-08-31 并入）

来源：宝玉解读 Claude 官方博客《How Warp builds self-improving agents on Claude》（2026-08-29）。核心机制：别让 Agent 自己进化自己——双 Skill 结构吃人类反馈（一个干活 Skill + 一个「改 Skill 的 Skill」定期收集人类工程师评论并更新前者）。反馈零摩擦：人在正常工作里随手评论 = 标注，收集/更新全自动。这正是「人标注 → AI 改进」的分工——桑老哥纠正铁柱 → 更新词条，就是它的手动版。

六条实践

  1. 写原则不写死规则（写给聪明人）
  2. 解释为什么（能推理能举一反三）
  3. 反馈零摩擦
  4. Skill 精简 + 渐进式披露（引用资源不塞满上下文）
  5. 反馈质量 > 数量（资深详细反馈远胜点赞数）
  6. 「改进 Skill 的 Skill」可复用到其他 Skill
防线：永远不让 Agent 盲目吃反馈——限制反馈权重 + 人审核。有标准答案的领域才全自动（宝玉反编译 skill 越进化越强）；没标准的靠专家（他写作 skill 自我进化负优化，越改越糟）。

前提与局限

  • 自进化改的主要是 Harness 这套脚手架，不是模型本身——别把宝押在「模型变聪明」上
  • 评估环境本身也是被攻击面：高分先查沙箱，再谈成绩（假满分陷阱）
  • 没写回、没跨任务验证、没独立批准的「越用越好」，一律先当假象处理

桑老哥适用

  • 桑老哥 = 独立裁判：铁柱自评不算数，看结果点头才算——控制面分离已在用
  • 「桑老哥纠正铁柱 → 更新词条/CLAUDE.md」= 手动版 Learning Loop；存 memory / 存 skill = 写回
  • 技能进化 是 Skill 层案例：60 分上线收失败案例，迭代到 90 分
  • Learning Loop 完整闭合：循环工程 保存现场→提炼问题→定义验收→选层→候选→独立验证→发布→观察→撤回或巩固；目标契约与五个闸门 是「定义验收」的日常版
