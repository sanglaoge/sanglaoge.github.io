AI原生开发手册

稳定 建条 2026-08-27 下次复核 2026-11-27

一句话说清楚

写代码不再是最慢的环节——瓶颈挪到了前后两头；官方解法 = 文件落盘接力 + 三件套管控 + 循环自转，人只守门禁。

这是什么

Anthropic 官方 2026-08-21 发布的内部最佳实践：怎么把软件开发的六个阶段（规划→设计→构建→测试→部署→运维）整个围绕 AI 重造一遍，把"每阶段人做、靠开会交接"的直线流程，改成"AI 嵌进每个节点、靠文件接力"的循环。

桑老哥的用法：不用真去开发软件，把它当"铁柱这套工作方式的官方总说明书"读——CLAUDE.md、skill、hook、memory、红黄绿灯在里面全部有出处、有分工原理。与 AI工程技能地图（吴恩达版 = 个人技能地图）互补：这本是组织流程地图。

核心判断：瓶颈挪窝了

AI 把写代码变快了 10 倍，整条链却没变快——因为堵的不再是写代码，而是前后两头人工环节：前头规划、开会、写需求；后头审查、测试、部署。

比喻：快递分拣中心换了超快分拣机，打包和送货还是人工，整条链照样堵。三个连锁后果：①瓶颈转移到构建两侧；②逐行人工审查跟不上 agent 的产出速度（管控和现实脱节）；③例外还得开会、会又少（治理成本上升）。

背景数据（文章引 Sensor Tower/金融时报）：App Store 销售额十年来首次下降——"随便做个软件就能卖钱"的时代结束，以后拼流程效率。

变成考题

妙处：提交链本身就是审计链——谁提的需求、AI 干了什么、谁批的，全留痕。铁柱对照：学习账本 / 概念库词条 / progress.md 就是这个思路——干完活落盘，下次会话读盘接着干，不用桑老哥从头交代。

循环自转（closing the loop）：每个生产事故变成一道考题（eval）永远留在体检套件——同样的坑不掉第二次；监控脚本发现线上异常 → AI 自动写成新的 intent.md → 流回第一阶段，"循环开始自我喂养"。

四个支柱

① 文件落盘接力

交接不靠开会靠文件，git 提交链 = 审计链（见上节流程条）。

② 管控三件套（分工是精髓）

CLAUDE.md新人入职须知 · 每次会话都读 · 铁柱的实物：全局+项目 CLAUDE.md，"同一错犯两次就写进去"，一页以内
Skill操作手册 · 建议性——用时才翻，让违规变少见 · 几十个 skill
Hook门禁闸机 · 强制性——不过就拦，让违规几乎不可能 · 日记 hook、审批门禁

③ 人只守门禁

人的注意力跟着"需要审查的产物"走，审 AI 标记出来的东西，不用从头盯。进不进下一关，永远人拍板。桑老哥的红黄绿灯系统就是官方说的 approval gate：绿灯直接干、黄灯干完汇报、红灯等点头。

④ 循环自转

事故变考题永久留评测套件；监控异常自动开新 intent.md 流回第一阶段。铁柱对照：memory 里"勿轻言工具坏"（0710/0715 两次事故变成永久规则）= 事故变考题的活例子。

小白说法专业术语

轻记一：吴恩达「软件工程基础」（2026-08-31 并入）

来源：Andrew Ng X 帖 2026-08-29（WaytoAGI 转载），技能地图四顶层之 ② 的展开篇。核心一条：代码可以外包，"知道有取舍"外包不出去——不懂基础的人让智能体干活，AI 在延迟/成本/可靠性/可维护性上替你做了糟糕选择，而你连问都不会问（权衡清单不在你脑子里）。

五块知识一句话：全栈应用｜数据管理（数据架构选错，AI 不知道自己缺什么）｜系统架构（随项目阶段演进）｜安全可靠（测试+故障设计+左移）｜生产运维（SDLC/CI-CD/可观测）。记忆语法这类知识在过时，但理解原理的人远胜凭直觉编码的人。

桑老哥的翻译版：不需要动手做这五件事，但要知情权——不动手，知道该问什么（图片压缩 = 成本与速度取舍、删库前备份 = 可靠性、先想布局再动手 = 架构）。概念库干的就是攒这份权衡清单。

轻记二：吴恩达「使用编码智能体」（2026-09-07 并入）

来源：Andrew Ng X 帖 2026-09-04（WaytoAGI 转载，lark-cli 抓正文），技能地图四顶层之 ③ 的展开篇。核心一句话：用编码智能体的高层流程就三段（规划→执行→部署与监控），五大核心技能决定你会不会用——社交媒体吹的"跑几小时几千万 token"被官方打脸，最有效的使用是"高度迭代 + 高超判断力干预"。

高层三段流程

阶段干什么人 vs 智能体配比
规划头脑风暴+研究+实验+理解代码库 → 写规格说明 → 生成执行计划 + 审查关键假设/安全性/过度设计人主导前期
执行构建+测试+验证，校准智能体自主性智能体主导
部署与监控CI/CD 流水线+人工关卡，智能体监控日志+发现问题+提改进人把关放行

要点：每阶段都可能因反馈回到前一阶段（验证失败引导重建、监控问题让智能体更新重部署）；流程高度迭代——不是直线。

五大核心技能（桑老哥对照表）

#技能大白话桑老哥对照
1引导工作流知道每步花多少人工/智能体力、何时返回上一轮迭代红黄绿灯定节奏
2实现智能体自主性选自主档位；管理上下文；多智能体并行编排skill（建议）+ hook（强制）分工，即 MCP-Skill-Hook三件套
3审查工作成果设计匹配任务的测试+验证；评估集+LLM 当裁判出稿评审分离法、AI确认偏误、红黄绿灯
4定制智能体及其环境装 skill/MCP 插件；hook 自动化重复部分；维护常设上下文这就是铁柱这套——Harness、Agent工程规范
5编码智能体基础懂代码库检索、上下文窗口、Harness 包裹 LLM 的方式Harness 词源直觉+六可框架

自主性旋钮（不是开关）

观察+对话

小步快跑，人随时介入

委托大块

智能体独立完成大段任务

循环到成功

明确目标让它自己跑到过

同一项目不同阶段旋钮位置不同。吴恩达官方反共识警告：社交媒体鼓吹"智能体跑几小时消耗数百万甚至数千万 token 有用"——"实际效用被夸大到超出实际程度"，最有效的使用是高度迭代 + 高超判断力干预。

失败模式清单（对照检查）

  1. 过度设计简单方案
  2. 缺明确验证过程 → 失严谨
  3. 还没达目标就停
  4. 操作可能搞坏文件/生产数据（红黄绿灯中红灯场景）

一句话带走：用编码智能体不是"让它自由发挥"，是"流程三段 + 五大技能 + 自主性旋钮"——会的人像指挥家，不会的人像被指挥。

边界提醒

  • 这是 Anthropic 内部（工程团队）的打法，受众是开发组织；桑老哥取的是骨架思想（落盘/门禁/三件套分工），不是照抄软件流程。
  • 全自动闭环（监控自动开 intent.md）的前提是门禁和 eval 都已成熟，跳过门禁直接上自动化 = 裸奔。
  • App Store 下降数据转引自 Sensor Tower/金融时报，原图未直接核对，当背景看。

一句话带走

看到流程卡，先问：瓶颈还在写代码吗？不是的话改两头——前头落文件，后头设门禁，人只签字。
