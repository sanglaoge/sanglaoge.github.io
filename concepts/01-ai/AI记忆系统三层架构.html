AI记忆系统三层架构

稳定 建条 2026-08-03 下次复核 2026-11-18

一句话说清楚

让 AI 跨会话记住重要信息。三层你中有我我中有你——索引常驻、详情按需、档案搜索。

AI 每次对话都是「新员工」——不知道你是谁、上次聊了啥。记忆系统就是给 AI 一个「笔记本」，让它跨会话记住你的事。

三层怎么分工，正好呼应 上下文组织原则 的分层加载：索引常驻、详情按需、档案搜索——一层对一层。

三层台阶：越往上越进阶，也越贵

便利贴第一层

内置记忆

方式：MEMORY.md + USER.md（AGENTS.md / CLAUDE.md 同层）

每次自动注入，零成本。装高频小偏好：语言、工具路径这类每次都要用的。

零成本 · 每次都带
档案柜第二层

外部向量库

方式：MemOS，按相似度检索

按意思翻、问到了才翻。装大段历史和知识。每轮至少 2 次 API 调用，贵。

贵 · 每轮至少 2 次 API
翻老档案第三层

Session 搜索

方式：全文检索历史对话

用才花钱。平时不动，要翻很久以前的会话时才去搜。

用才花钱

台阶越高越进阶：第一层天天免费在用，第二三层按需再开。

桑老哥实操配置映射（2026-08-20 对齐确认）

配置属于哪层说明
AGENTS.md（全局规则）第一层 · 内置记忆任何会话启动自动读，便利贴
CLAUDE.md（项目规则）第一层 · 内置记忆进项目自动读，便利贴
MEMORY.md（对话中觉得重要让铁柱存）第一层（动态便利贴）跨会话自动带，内容是追加的
MemOS（向量库）第二层 · 外部向量库按相似度检索，按需翻，档案柜
跨对话 session 共享（A区聊B区能用）第一层+第二层组合MEMORY 共享文件被多会话读 + MemOS 跨会话检索
调优：memory_char_limit = 4000（默认 2200 太容易满） nudge_interval = 5（每 5 轮提醒存记忆）

关键区分：便利贴 vs 档案柜

MEMORY.md · 便利贴

每次开工自动全量读——「每次都带」。

MemOS · 档案柜

按意思检索才带——「问到了才翻」。

注意（呼应三坑）：MEMORY.md 别塞太满——它每次自动全量读，塞太多挤占对话窗口。存之前判断：每次都要用的偏好进 MEMORY.md，偶尔才查的背景进 MemOS。

从零手搓的记忆循环（2026-09-19 Jaydeep 并入）

纯 Python + SQLite + Ollama 无框架实现（智能体记忆七部曲之三，GitHub 仓库 AI_AGENT_MEMORY 可跑），五个增量认识：

  1. 对话历史 ≠ 记忆——把聊天记录原样发给模型只是复读，清空 messages 即失忆；记忆 = 对话结束之后还活着的东西（接 上下文工程「草稿纸 ≠ 记忆」的钩子）。
  2. 检索与提取是两个独立问题——检索答「旧记忆里哪条现在有用」，提取答「这条新消息值不值得记」。混在一起系统就是浆糊，分开做每半边可单独检查（与 出稿评审分离法 同思想）。
  3. 模型提建议，程序拍板——LLM 只返回结构化建议（该记吗/记成什么/类型/重要度/置信度），存不存由代码决定，不给模型直连数据库的权限——判断归人的工程版，防模型往库里塞垃圾。
  4. 召回不是纯相似度——评分 = 语义相似 70% + 重要度 20% + 置信度 10%（作者自标非金科玉律，权重按实际检索质量调）。纯相似度会让重要的记忆淹没在「差不多」里。
  5. 存储容易找对难——记忆系统全图是七问链：记什么→怎么表示→存哪里→何时取→多相关→注多少→还准吗→该忘吗。向量库只是其中一个零件。

前提与局限

  • 内置记忆最常用，但窗口有限——不要塞太多
  • 向量库贵——每轮都调 API，非高频不用
  • 三层不是三选一：索引常驻打底，档案柜和老档案按需补

桑老哥适用

  • 你的 CLAUDE.md 就是第一层——每次铁柱启动自动读；MEMORY.md 跨会话记住你的偏好和决策
  • 这是免费层，用好就够；MemOS（第二层）和 Session 搜索（第三层）是进阶，需要时再开
  • 让铁柱读链接再回答比让它凭记忆答靠谱——用的就是「翻档案比背下来准」这条
