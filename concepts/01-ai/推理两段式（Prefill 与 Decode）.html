推理两段式（Prefill 与 Decode）

稳定 建条 2026-10-20 下次复核 2027-01-20

一句话说清楚

AI 出话不是"想好了再说"，是先一口气把你给的整段读完，再一个字一个字往外蹦。

这两段干的活完全不同——一段算得快、一段跑得慢；一段是首字延迟，一段是生成速度。AI 为什么卡、为什么越聊越慢、为什么省钱要清会话，全在这两段里。

它是三条已学词条共同踩的地基：上下文工程 讲"要省"，Tokenmaxxing 讲"怎么省"，System One判断模型 讲"Jev 快两个数量级"——三条都没讲为什么，这条补的就是那个为什么。

来龙去脉：补的是一层缺的地基

2026-10-19 腾讯技术工程 leonjia 发了一篇架构演进长文，从 2017 年 Transformer 一路讲到 2026 年的 Jev。它没教新工具，而是补齐了一块此前概念库没踩到的底板。

更早一次撞见是 9 月 29 日读知乎蓝宝书，当时判"跳过"只留了账本一行。第二次撞见时发现它同时是一堆已学词条的底层解释——能解释三条词条的知识，比它自己重要得多，于是升格成条。

这也是概念库的升格判据在起作用：同一概念第二次撞见，才建词条。第一次撞见时它还只是个技术细节，第二次才显出骨架的身份。

两段式：一次回答的两副面孔

对 Decoder-only 模型（ChatGPT、DeepSeek、Qwen 这一支）来说，"读懂你的话"和"往外说话"不是两个网络，是同一个网络、同一套参数的两个阶段。

第一阶段：Prefill（读）

把你给的整段 prompt 一次全喂进去

  • 能并行：所有 token 同时算
  • 瓶颈在算力：矩阵乘法密集
  • 你感知到的是首字延迟：问完话到第一个字冒出来之间的干等
  • 产出缓存：各层的 Key/Value 存进 KV cache

第二阶段：Decode（写）

一次生成一个 token，接回输入再生成下一个

  • 只能串行：一步等一步，快不起来
  • 瓶颈在访存：每步都要读全部权重 + 全部缓存
  • 你感知到的是生成速度：每秒蹦几个字
  • 追加缓存：新 token 的 K/V 接在缓存后面

读一次就完，写要写一长串，且每一步都重新读一遍全部缓存。

一个常见误解要拆掉：AI 不是先想完整段再输出，是边生成边"想"。后面每个字都要重新过一遍整个网络。所以"让它再想一遍"在机制上不存在——你只能给它新信息，或重开一次。

三个直接推论（这条词条真正的用处）

推论一

首字要等，之后顺

第一段要把整段话算完才出第一个字，后面每个字只算一小步。所以"慢"通常慢在开头。

推论二

聊得越长越慢越贵

KV cache 随对话长度线性增长，而 decode 每一步都要把它读完。上下文不是"多放点没关系"，是每一步都在付利息。

推论三

前缀一个字都不能动

缓存认的是"从第一个字起的完整前缀"。改了开头，后面全部作废重算。所以静态内容放头部，多变内容堆尾部。

这三条是可直接改操作的：首字慢就精简开头那段指令；越聊越卡就 /clear 开新的；CLAUDE.md 别每轮都改第一句——改一个字的代价是整段缓存重算。

GPT 凭什么赢：两个差异决定一切

2018 年前后，Transformer 被拆成三份用，长出三条路线。三者层结构几乎一样，实质差异只有两点：注意力能不能看到后文；训练时是填空还是续写。

只留读的

BERT（2018.10）

留 Encoder，双向能看前后文。训练做完形填空——遮词还原。

两半都留

T5（2019.10）

Encoder + Decoder 都在。训练是遮一段再补出来。

只留写的

GPT-1（2018.6）→ 今

只留 Decoder，因果掩码看不到后文。训练做接着往下写。

GPT 赢的三条原因：

  1. 训练信号更密——续写是"每个位置都是一道题"，填空只有被遮住的少数位置有题。同样一批文本，续写的训练密度高一个量级。
  2. 任务形态统一——对话、代码、推理、调工具，全都能写成"在同一段里接着写"，不用为每类任务重造输入输出。GPT-3 的"上下文学习"（只看几个示例就会新任务）正是这种统一带来的。
  3. 缓存能复用——因果掩码保证已算过的 token 不受后面影响，多轮对话只往后追加；双向 Encoder 每次新增输入都要重算。

BERT 没死，它退到了检索、推荐、内容审核这类"读一次就出结果"的高吞吐场景（2024 年的 ModernBERT 就是当代版）。它的活法是预训练 + 微调：任务和类别在训练时就焊死了，换任务得重新标注重新训。

后训练没改架构，改的是"性格"

ChatGPT 的对话能力不来自结构变化，来自预训练之后的几轮后训练。这一段同时解释了另一件事：校准就是在这一步塌的。

阶段干什么结果
预训练几万亿 token 续写会接话，但不会当助手
SFT 指令微调人写的问答对学会问答格式
RLHF人给多个回答排序 → 训奖励模型 → 强化学习偏移像个助手了，但概率变不准
推理 RL只看答案对错数学/代码变强，延迟从秒级变分钟级
关键副作用（OpenAI 在 GPT-4 技术报告里给过对照）：预训练模型说"八成把握"，大约就八成答对；经过后训练之后，这种一致性明显变差。原因是标注的人偏爱语气确定的回答，模型就学会了"看起来对"，而不是"概率反映真实正确率"。

这条因果链是 System One判断模型 存在的真正理由：自动化卡住的不是能力，是它说不清自己哪 5% 会错。

Jev 为什么快两个数量级：它根本不进第二段

这是整条词条最值钱的一条辨析。普通模型和"结构化输出"都在逐 token 生成，只是后者被格式约束；Jev 干脆没有生成过程。

普通大模型JSON 模式 / 结构化输出Jev
读完输入是是是
逐 token 生成是是（一步没少）否
输出一段文本一段被格式约束的文本每个选项上的概率
表述串行采样串行采样 + 格式约束并行采样

所以"类型安全"不是产品包装：它压根没有生成过程，不可能说出选项外的话。但它照样可能选错——schema 零错误 ≠ 判断正确。

开源对照 Laya（Convai，9-18 开源，Apache 2.0）：输出方式跟 Jev 一路（读一次、按选项读概率、以校准为训练目标），底层却是 ModernBERT-large 上接个决策头——把选项写进输入序列，在选项前的 [MASK] 位置读分做 softmax。它也印证了对 Jev 的推断：去掉"生成"这一步不难，难的是底下那层能零样本读懂任意问题的理解能力。

2026 年的前沿模型：动的是内脏，不是骨架

DeepSeek-V4.1-Flash（9 月，总参 552B / 每 token 激活 16B）和 Qwen3.8-27B（8 月开源，27B 全激活）——都还是自回归、逐 token 生成的 Transformer，prefill/decode 两段式原样适用。创新只发生在两处，目标一致：同等能力下省算力和显存。

  • 前馈网络改 MoE：每层拆成几百个子网络，每个 token 只激活少数几个，把"总参数量"和"每 token 计算量"解耦。
  • KV cache 压缩：长上下文和 Agent 场景下缓存竞比权重还占地方。DeepSeek 用低维潜向量 + 稀疏选择，还把前 20 层当因果 encoder、后 20 层的 KV 由它投影出来（prefill 只跑一半网络）；Qwen 自 3-Next 起每 4 层拿 3 层换成线性注意力（Gated DeltaNet），用固定大小状态替代逐 token 缓存。
判断一个模型属于哪条路线，别看名字，看两点：注意力是不是因果掩码；结果是不是逐 token 生成出来的。

错法 → 对法

错法对法
把 AI 当"想好再说"，反复重问同一段对话想让它"重新想想"它每次都重走一遍 decode；要它换思路，就给新信息或开新会话，别指望"再想一遍"
想到什么就往对话里加，觉得上下文不要钱每一步都在读全部缓存，长度是每一步的利息。不相关就 /clear
每轮都改 CLAUDE.md 开头一句前缀一改，全部缓存作废。稳定内容放头部，多变内容堆尾部
以为加了 JSON 约束就等于"不会胡说"约束的只是字符串形状，逐 token 生成一步没少；要靠校准，不靠格式
以为新模型出来架构变了、旧认知作废骨架 2017 年至今没变过，变的只是内部组件和训练方式

前提与局限

  • 本文的 Jev 实现细节（底层是预训练因果 Transformer + 并行分支 + softmax 读头）是作者从 API 行为推断，不是官方披露——别当定论。
  • prefill/decode 是 Decoder-only 主线的说法；Encoder-only（BERT 系）只有一次前向，不适用。
  • BERT 系在固定任务上、标注充足时，往往比零样本的通用模型更准——"GPT 赢"说的是通用能力，不是所有场景。
  • 推理模型的思考过程仍然是逐 token 自回归生成，只是不给你看，所以延迟照旧。

桑老哥适用场景

  • 解释了三个日常体感：为什么首字要等、为什么长对话越聊越慢、为什么"任务干完就关会话"确实省钱。
  • 一个可直接用的判断：任何号称"快 100 倍"的模型，先问一句——它是不是跳过了 decode？跳过的多半只能做判断题，做不了写作。
  • 工具选型有底了：要写文案、做图说明、出脚本 → 走生成式（要 decode）；要分流、要打标、要"这条消息急不急" → 判断题类工具（不 decode）才对。
  • 别拿"重开一次让它再想想"当优化手段，那只是重烧一遍电。
  • 以后遇到"AI 怎么变笨 / 变慢 / 变贵"，先想两段式，再去查别的。
