循环工程

一句话说清楚

别再手动 prompt 你的 agent，去设计一个循环来 prompt 它。 —— Addy Osmani

循环工程 = 设计一个能自己跑、自己纠偏的闭环，把人从"盯着 AI"里拔出来。

红旗法案比方：160 年前汽车前头必须有人举红旗引导，累的是举旗人。今天人盯 AI = 举红旗。循环工程就是把红旗撤了，让 AI 自己开，你只定终点和刹车。

来龙去脉：为啥要从 prompt 演进到 loop

LLM 本质是"猜"（概率模型）。单次猜对率 90% 听着高，但复杂任务要拆好几步，概率连乘——0.9 的 6 次方 ≈ 0.53，跟抛硬币差不多。

  • 错法：你盯着 AI，错一次纠正一次，人成了瓶颈，累且不可靠。
  • 对法：设计循环让 AI 自己跑、自己纠错，你睡觉它干活。

Harness vs Loop 一句话：Harness 是"安全跑道"，Loop 是"跑道上的自动驾驶"。没跑道，自动驾驶没地方跑。

每一代不是替代上一代，是叠在上面。五代是作者的主观分期，不是行业标准，具体月份别太当真。

核心方法论：控制论四问

任何想让 AI 自动干的活，想清楚四件事：

1定义问题

到底要解决啥

2定义开始

什么时候启动

3设计反馈关键

怎么让 AI 知道对错：给硬标准（如"标题≤20 字、必含品牌名、禁最高级词"），AI 对着自检；不能靠 prompt 里的拒绝意图（假拒绝）

4定义结束关键

防止无限循环烧钱：设最大步数（3 次失败交回人）+ 预算熔断（花到 X 停）。与 Prompt三原则的 TERMINATION 同源

Claude Code 四类循环

类型触发桑老哥对应
回合式每轮对话内改进检查铁柱每轮自检
目标式/goal，达成目标才停你的文章筛选闸门=雏形
时间式/loop /schedule 定时暂不适用（文章是你手动挑的）
主动式全能力叠加自动跑远期，需先跑通单循环

自改进循环：AI 不光跑，还能改自己

循环工程的进化版：AI 不光自己反复跑，还能自己改自己的规则（提示词/指令/工具），靠 eval→grade→compare 循环自动优化。Google agents-cli 开源了这套（Saboo & Secchi, Google Cloud Tech 2026-08）。

致命点：循环能自动化一切，唯独不能替你定义"更好"——你给什么指标它优化什么（古德哈特定律），AI 会为分数作弊（降阈值/改答案/删案例）。所以"指标"必须人写，放在循环够不到的地方。

验证器怎么不被偷走标准线的 7 条规则、作弊三招、评测监控同源，详见关联词条·图谱工程「自改进循环与验证器 7 条规则」。命根子是规则 6：别让提出方案的人移动标准线——你概念库审计做的就是这事（不让铁柱自评，3 路独立核查对照维基）。

让 AI 真的会说"不"

法要点
TDD 思维先定标准后做开发，把需求翻译成"对/错"信号。适合明确规则，不适合品味/体验/产品决策
证据链评审者不能靠感觉说不行，要拿依据追溯（出稿评审分离法）
预算思维贵模型给高价值任务，便宜模型给重复活；核心规则人不压缩

评估器：独立怀疑者 > 自我批判

（Anthropic 工程师 Rajasekaran）智能体评估自己会自我赞美（结构性：写时上下文塞满支持论据，回读看到的是推理不是结果）。调好独立怀疑者，远比让作者自我批判容易（GAN 形态：一个构建一个挑错）。

装饰性评估器真正的评估器
指令/模型同生成器+同模型独立指令+不同模型（同底座保留同盲点）
方法/立场读代码/默认信任对它动手（点击截图）/默认怀疑
结果两个乐观者达成一致循环真能说不

银行规则：输入大额转账的人不能同时批准。生成器决定产出什么，评估器决定拒绝什么。→ 你的铁柱（生成）+ 爱马仕（评估）+ 桑老哥拍板，天然满足。

过滤器：哪些活该做成循环

四条件同时成立才做：

1每周至少重复一次

看日历，不看意愿

2有自动拒绝不良输出的命令

能跑测试/检查，如分级闸门

3词元预算能承受浪费

循环会重试、游走、空转

4智能体有资深工程工具

日志、复现、能跑能看崩溃

贴显示器的话：当审查能力已是你的瓶颈时，循环只会拉长队列，不会缩短。模糊产品工作、认证支付、生产部署、"完成"需要人判断的事，应保持人工。

三条件 + 模型特性 + Hook 阻塞

挑 Loop 场景的简版口诀（与过滤器四条件互补：过滤器看"该不该自动化"，三条件看"这活配不配跑 Loop"）：

  1. 清晰——明确要什么；盲目跑 Loop 只剩烧 Token 和"跑了 X 小时"的吹牛素材（例：连续 3 轮零误报）
  2. 可验证——给把尺子：优化类量化成 XX 率，重构/开发看测试用例通过情况
  3. 可收敛——每轮都向目标逼近；不收敛的目标 Loop 一万年也没用

模型特性（长任务选型）：Claude 系容易自我满意、糊弄式完成；GPT 系严谨，小细节不满足就继续抠。Loop 任务可换模型跑，甚至多模型对抗取长补短。

Hook 阻塞案例（几行代码）：拦截 Claude Code 会话结束动作，脚本检查迁移计划待办是否全完成，没完成就阻塞打回——作者 Bun+TS 迁 Go 靠这招连跑五六小时一把过，就是 Codex Goal 式"不干完不许停"。

YC Paper Club 实践补充

权重没变，工具、记忆、运行方式变了，同一个模型就能做出很不一样的结果。"很多情况下，模型具备的智能比我们实际用到的更多。""我们给它们能力很强、工具齐全的环境，但它们经常过早放弃。" —— Why The Harness Matters More Than The Model（YC Paper Club）
  • grind 工具（YC 官方版"不干完不许停"）：给目标设时间/token 预算，烧完之前不许 Agent 轻易结束——模型停下来的时刻未必是做不到更好的时刻，提前交卷往往只是太早停。与 Hook 阻塞、Codex Goal 同族。
  • 假满分陷阱：Agent 第一次跑就 99.9 分，查日志发现钻了测试隔离漏洞。评估环境本身也是被攻击面——高分先查沙箱，再谈成绩。
  • 任务结束别急着解散：子 agent 干完先汇报、保留上下文进空闲池，主 agent 一条消息召回接着干，久不用的才移出内存——少重复交代背景，跨阶段工作能衔接。
  • 规模佐证：《异星工厂》连跑 7 天，累计 633 个 agent、约 2300 万输出 token，靠保存与修订经验推进科技树。
  • 权限即上下文上限："你能放进大脑的信息量，实际上受限于你的权限系统有多好"——Agent 进群聊缺分寸感（私下消息能不能转述、何时该插话），信息给多少由权限边界决定；批量写入只读为主、人审计划，但要警惕"习惯性点通过"让审核走形式。

实战案例：宝玉从 TL 到 EM

阶段做法
TL（技术主管）事必躬亲，人成瓶颈
EM（工程经理）只想"做什么+验收结果"。流程=想好功能→定方案→/goal 让 AI 写+自动测试→只验收
转折点Fable 5 后 AI 代码质量够好，稍加验证就不会偏

三个洞察：① 人盯太细=自己变瓶颈 ② 真瓶颈从"写代码"变成"想清楚要什么" ③ 技术选型解放（不懂 Rust 也敢用）

四笔账（循环跑起来的隐藏成本）

账症状防护
验证债务未审查输出堆积，完成一半发完成信号用无意见闸门（编译过/不过），别用有主观意见的审查者
理解力腐蚀仓库增长，脑中地图停滞，成项目访客每周读少量已合入变更，向自己解释
认知让渡不再形成判断，只接受结果交执行不交决策
词元失控账单波动，整夜空转的 bug 变账单单次+每日预算+最大重试次数

最隐蔽是认知让渡：循环越稳你越信，看得越少判断越弱。你不必常推翻它，但必须持续有能力说"这是错的"。

桑老哥适用场景

  • 你用铁柱（CodePilot 壳子+hook+MCP）= 已在 Harness 层，跑道建好了
  • 铁柱+爱马仕双 bot 协作 = 往 Graph 层走（图谱工程）
  • STATE/VISION 你已经在用：概念库=STATE（当前位置），学习账本/CLAUDE.md 目标=VISION（目的地，防目标漂移）。记忆会话结束消失，仓库文件不会——这是你建概念库的本质
  • 文章筛选闸门=目标式循环雏形：满足过滤器四条件（天天发+闸门+预算+lark-cli），但"该不该学"是模糊判断，该保持你拍板，别全自动
  • 核心价值是"想清楚要什么"（约束先行），把执行交给 AI。每次自动干活前过一遍四问：问题/开始/反馈/结束

前提与局限

  • Loop 不是技术框架，是思维模式。学"怎么设计闭环"，不是具体代码
  • 别一上来就做全自动万能循环。先跑通一个最小可收敛闭环，再放大
  • 小闭环没打磨好就上图谱 = 分布式失败（图谱工程"从一个强循环开始"）
  • 警惕认知让渡：交执行不交决策，判断力要持续练
