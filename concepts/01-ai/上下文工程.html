一句话说清楚

管好 AI「眼前能看到什么」的功夫。不是塞越多越好，是对的时间给对的信息。

来龙去脉：Context Rot（上下文腐烂）

AI 的「注意力窗口」像一张小书桌——大小固定，新信息进来，旧的就被挤下去。这带来一条铁律：对话越长，AI 越笨。不是 bug，是物理规律。

三个原因

① 注意力摊薄——每个 token 都要跟窗口里所有 token 算关系，多了注意力就稀疏；② 训练偏差——训练数据大多是短对话，长文天生不擅长；③ 旧垃圾污染——失败的 debug 路径留在上下文里，AI 会反复踩同一个坑。

找钥匙比方

就像请人找钥匙，你跟他说「去过厨房、客厅、卧室、车库……」他脑子被塞满，反而更难想起钥匙在哪。

核心公式：思考空间

思考空间 ＝ 上下文窗口上限 − 已用内容你塞的信息越多，AI 能「想」的空间越少——跟人完全一样
反直觉阈值：上下文用到 50% 之后质量就开始掉——别等满了再处理。
出处注记：50% 是个人体感/经验值，非权威数据点（Chroma Research 论文未给出此阈值）。

Session 管理五把刀

每次 AI 回完话，5 个操作可选：

操作干啥什么时候用
Continue接着说上下文干净，继续干同一个活
Rewind（双击 ESC）时光倒流AI 走错路了，干净重来，别纠正它
/clear清空重来换任务了，你亲自写简报带过去
/compact让 AI 压缩同一任务但 session 长了，必加 hint
Subagent派分身大量脏活只要结论，不弄脏主 session
Rewind > 纠正：别跟 AI 说「这样不行换个路子」，直接双击 ESC 回到走错之前。失败的路径不留在上下文里。

Claude 5 时代：少写规则，多给判断标准

Claude Code 砍掉了 80% 系统提示词，评测没变差。旧模型靠护栏，新模型靠判断。

旧做法新做法
给规则（禁止清单）给判断标准（啥情况下咋干）
给一堆例子让它猜设计清楚的工具接口
所有信息开场全塞渐进披露，需要时再加载
重复强调同一件事工具描述简单清楚

不适用边界：高风险硬禁止（不要删文件、不要推代码）继续用「不要 X」。

七类构成与五大反模式

七类构成（「给什么」的完整清单）：系统指令＋用户提示＋状态历史＋长期记忆＋检索信息＋工具定义＋结构化输出。

总配方一条：最优上下文 ＝ 最小 Token × 最高信噪比。

五大反模式（踩了就变笨）：①堆信息求安全 ②工具越多越好 ③系统提示越细越好 ④不清理工具旧结果 ⑤指望大窗口一劳永逸——大窗口只是推迟问题，不是解决问题。

ReAct 四陷阱与破解：工具返回膨胀→截断摘要；规则漂移→关键规则放开头结尾；错误污染→失败路径及时清出；思考冗余→压思考预算。

工具加载三方案：MCP / Skill / CLI

三个方案都在回答同一问题：怎么让上下文干净、强相关。

MCP＝全量加载

装上就常驻——实测有新开对话啥没干，工具定义先吃掉 20% 窗口。但高频触发＋工具精简的 Server 依然好用，别判死刑。

Skill＝渐进式披露三层

一句描述→SKILL.md→references 按需加载。描述要写「什么时候用我」而非功能概述（职责重叠会误触发）。两维度迭代：触发稳不稳＋输出好不好。

CLI＝AI 的母语

训练数据里 shell 用例海量，--help 自带说明书，天然渐进披露。三条铁律：①用标准范式别发明新协议 ②每个命令/子命令必须有 --help ③支持 JSON 输出——AI 用 jq 管道串接工具，中间数据在管道里流转、不进上下文。

组合拳

CLI 管「能做什么」，Skill 管「什么时候用、怎么用好」，MCP 留给高频精简场景。别争论谁取代谁——都是「管理上下文」这一个问题的不同补丁。

长任务记忆三层存放＋会忘

长任务不能只靠对话窗口硬撑，信息分层放：

当前对话眼下要用的内容
持续运行的环境（Python 状态）数据和变量——写程序处理内存里的数据，只把结果带回对话，省掉反复读原始材料
文件长期记忆、技能、提示词，按需取用不占窗口
铁律：让模型能找到并处理信息 > 要求它当场记住全部。

另一半是会忘：变量、子任务、记忆文件越攒越多，清理要纳入框架（更新过时的、删无用的、整理经验）。只会记不会忘，系统照样被撑死。

底层机制与成本：为什么要省

两层记忆结构

权重＝长期记忆（训练烧进去的，稳定改不了）｜上下文窗口＝短期草稿纸（会话结束就消失，有限、贵、可管理）。推论：AI「记不住你」是正常的，跨会话连续性全靠外部文件落盘。

KV Cache——前缀缓存的经济学

  • 前面算过的内容可缓存复用，命中价只要原价的 1/10 到 1/50
  • 缓存认「前缀」——从第一个字起一字都不能变：改开头＝后面全作废，改结尾＝只破尾部。所以静态内容（系统指令/CLAUDE.md）放前面，动态对话放后面
  • 缓存有保质期（几分钟到一小时），省钱主要省在同一会话内——任务干完再关，比频繁重开划算
  • Q/K/V 一句话：Q＝一次性提问条不缓存，K/V＝反复被查的索引卡和内容笔记才缓存

注意力是聚光灯（实测佐证）

把正确答案埋在一堆资料中间，正确率 35%-45%，低于完全不给资料的约 56%——喂错比不喂更糟。「大多数 Agent 的失败已不是模型失败，而是上下文失败」（Philipp Schmid）。

Claude Code 的账单（X 光片）

约 25K token 开机费，构成如下：

工具定义40%
官方主指令20%
项目 CLAUDE.md16%
memory12%

六个 Token 杀手：①膨胀的 CLAUDE.md ②贪多挂 MCP（光挂载就能吃掉约 20% 窗口）③滥堆 Skill ④失控的工具输出 ⑤拖沓的历史包袱 ⑥失控的 Thinking tokens。

五级防御从轻到重：文件落盘 → Snip 裁剪 → Micro Compact（留近摘远）→ 工具结果折叠 → Full Compact（九维摘要开新会话；会话摘要＝短期记忆的「遗言」，Codex 同款四要素：进度/决策/待办/关键数据）。

桑老哥已在做的：CLAUDE.md 80 行红线、skill 精简、抓文章用切片＝防杀手②③①；干完一票 commit＋关会话＝防历史包袱＋吃满缓存。边界：25K/占比等数字来自作者逆向分析，量级参考非官方。

三秒自检

  1. 前面这堆上下文，还和我接下来要做的事相关吗？→ 不相关就 /clear
  2. 我要的是中间过程，还是只要结论？→ 只要结论就派 Subagent
  3. 有没有一条路应该回去重走，而不是往前继续？→ 有就 Rewind

桑老哥适用

  • 你用铁柱聊天时，对话越长越容易出问题——这就是 Context Rot
  • 50% 窗口就该主动 /compact，别等满了
  • 大量脏活（搜资料、批量处理）派 Subagent，别弄脏主对话

前提与局限

  • 上下文窗口是物理限制，不是模型不行
  • 中间最易丢：开头结尾记得牢，中间的最容易被忽略
  • 高风险硬禁止（不要删文件）仍然用「不要 X」
