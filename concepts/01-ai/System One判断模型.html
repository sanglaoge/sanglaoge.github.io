System One判断模型

稳定 建条 2026-09-19 下次复核 2026-12-19

一句话说清楚

只做判断题，不写作文——ChatGPT 给人写答案，Jev 给程序做判断。

平时让大模型干的事，一大半根本不需要它写作文：判断一条内容要不要进日报、判断客户要退款还是问物流、判断 Agent 下一步调哪个工具——全是判断题。System One 模型把「判断」这一个环节单独做成了模型类目。

来龙去脉：一道判断题的浪费

以前为了「这条留言在骂客服吗」这道判断题，得动用几十上百亿参数的大模型：等它慢吞吞吐两秒钟字、花几分钱、再写一堆防御逻辑从它吐出的废话里抠结果。

TypeSafe（旧金山创业公司，2026-09-15 出隐身，4000 万美元种子轮，创始人 Diogo Almeida 是 InstructGPT 论文作者之一）把这一环节做成了独立模型类目：

  • 类目名 System One：取自卡尼曼《思考，快与慢》的快思考（System 1）
  • 首模型 Jev：取自提出杰文斯悖论的经济学家——判断成本降到一分钱以下，判断的用量会不降反升

三种题型（打分卡）

Noul

判断题

是/否。如「这条留言在骂客服吗？」

返回：布尔概率（如 0.94）
Choice

选择题

选项定死的单选。如「工单归哪类？」上限 255 项

返回：所选项＋完整分布＋置信度
Score

打分题

在你描述的等级尺上定位。如「怒气值 1-5」

返回：分数＋分布＋置信度

杀手锏：读一遍材料并行答题——同一状态可挂十几道题，几百毫秒一起交卷，加题几乎不加延迟只加便宜 token。

为什么快、为什么敢信

快：不逐字生成（无自回归），输出层直接算概率分布——结构上吐不出格式外的值（「0% 类型错误率」是结构保证不是统计保证）
敢信：RLCD（强化学习校准决策）训练出校准的概率——说 80% 把握，一百次里真对八十次左右，模型自带仪表盘
门控：高自动放行 / 中转人工 / 低不动作——任何 AI 流程都能抄这个思路

用法三招

1

投机扇出

状态只发一次，问题全并行问（连「可能用不上」的也一起问）。别一次次顺序调用。

2

组合评分

别问「优先级多高」这种大问题，拆成几个 Score 在代码里加权（如严重度 0.6 / 愤怒度 0.3 / 报告质量 0.1）。排名不合意改系数即可，不用重写提示词。

3

意图路由

查订单走数据库不碰 LLM，产品咨询才叫大模型，投诉按「需要多少思考」分流转人工——贵的资源只为需要的请求开机。

短板红线（官方自曝 jaggedness 页）

  • 数数、精确算数、日期先后全不行——留给代码（数「列表里几个是水果」＝每项一个 Noul 再求和）
  • 中文比英文弱，上线前先小样本测试
  • 提示词注入仍有效——退款/资金/删库类高危动作，硬代码权限拦截该留还得留（＝「分析可全自动，花钱不行」金律）
  • 状态塞无关内容准确率就掉——判断模型也要做上下文卫生
  • 写题诀窍：描述情境，不描述程度（「功能损坏但有变通方案」有用，「中等严重」没用）

生态位：军师＋传令兵

大模型坐军师（拆解复杂任务/生成核心代码创意），判断模型当前线传令兵（工具分拣/条件路由/合规拦截）——一次用户操作背后可以是几十次隐形小判断，完全不显示 AI 界面。

LangChain 的 AutoMode 中间件已把「工具执行前先分级」做成现成零件（只读/可逆/不可逆，低置信度转问人）＝权限金律产品化；早期影子测试里一条模糊 rm -rf 拿到 0.33 低置信度，代码自动转问人而非瞎执行。

实测下半场：剔掉虚火之后的真实账

发布不到一周，huangserva 亲自跑了四败两成，比概念更值钱的是这层数据（2026-09-20 并入）。

「便宜 40-400 倍」的边界（最重要修正）：只对前沿大模型成立。300 判断对照实验里，Jev 94.7% 对 Qwen Flash 93.0%，各花 0.003 美元——对便宜大模型无成本优势。它真正多出来的只有两样：时间稳定（国内实测约 0.7 秒、最慢 1.5 秒，Qwen Flash 中位数相当但最慢 32 秒——赢在「无长尾」不是快）＋可分流的校准把握度。

失败一：Claude Code 压缩插件——为塞 32K 先砍内容，Jev 只见工具名不见内容＝无脑删
失败二：Codex 模型路由——反而多花 59-184%、每步多等 1-2 秒（代理把请求变重 2.5 倍还丢缓存）
失败三：自稿挑 AI 味——62 句误报 22 句
失败四：40 个大视频删除判断——判 0 个，纯规则能判 7 个

根因都不在模型：看不到内容 / 订阅制杀死经济学（Codex/CC 判断已含在月费里边际成本为零）/ 只会判断不会干活。217 个生态项目审计：今天真能用的 15 个里 14 个是 LangChain/pydantic-ai 等框架接口层，唯一应用是 browser-use 的 jev-ultrafast（机票搜索 9.5 秒→7.1 秒）。

三步落地法（huangserva 版）：列出业务里「LLM 只返回一个选项」的调用（没有就别追）→ 挑一个用真实历史数据盲测，重点盯 70%-90% 档的真实正确率 → 在大模型前加 Jev 闸门，90% 阈值起步看数据下调。

结论一句话：想拿它给自己提效，走不通；把它当零件做进产品，才有可能。

打分机制拆解：快 200 倍的原理

  • 改考卷不写作文：普通调用是自回归逐 token「写」答案；Jev 是预填充后一次读出所有候选的 logits，打分归一化直接交卷。警惕冒牌货——「让模型吐 JSON」（结构化输出）看着像选择题，其实仍逐字生成，一点没省。判断一个产品是否真用上决策模型：看它是生成答案，还是打分选择
  • 分数强弱本身是信号：两张工单都判给计费，91% 遥遥领先 vs 46% 几乎打平——margin（差距）大小决定自动处理还是转人工，阈值写在代码里归人定改（＝置信度门控的机制底座）
  • confidence ≠ 正确率：confidence 由分布集中度算出，分布集中也可能全错，不能当本次回答的正确率用；0.91 只是押注比例，拿带标签的真实结果回头对账才是校准
  • 本地可复现：Jev 闭源，但打分推理路径开源就能复现（SGLang /v1/score 接口＋Qwen/DeepSeek 实测）——护城河不在打分技术，在 RLCD 校准训练

部署方法论：7 步安全上线

  1. 选边界清晰的低风险决策
  2. 先定 rubric（评分标准）
  3. 采集含模糊/对抗样本
  4. 影子模式并行（先旁路观察，不接管）
  5. 画准确度-置信度曲线，按数据定阈值
  6. 先自动化最安全分支
  7. 固定模型版本/问题/标准/阈值，可重放

Agent 里第三种放法是「验证与监督」（测试过没？是否重复空转？输出合规吗？）。

幻觉要精确说：schema 错误 0% ≠ 决策正确 100%——它不会答选项外的答案，但会自信地选错合法选项（TypeSafe CEO 自己承认），合规错误仍会退错款。

玩法案例库（逛逛GitHub 汇编）：

40 秒拆 37 品牌 724 条广告只要 9 美分 浏览器查航班 7 秒 0.39 美分 MuJoCo 火箭回收 245 次调用 4 美分 游戏实时控制 0.7 秒/步 写作实时测传播潜力 用 Jev 给别的 Agent 压上下文（接 上下文工程）

桑老哥适用

视频工厂流水线里所有「要不要/是哪类/打几分」环节，现在有几分钱级的零件可换——2026-09-20 实测纠偏：咱用 Codex/Claude Code 是订阅制，判断已含在月费里边际成本为零，外加 Jev 反而多花钱，「零件」只在按 token 计费、调用量大的自建产品里成立。

  • 仍然成立的方向：把它当零件做进自己的产品（如视频工厂对外服务、选品工具），走 OpenRouter 免排队直调 typesafe/jev；自用提效路线已被四次实测证伪
  • 值得借鉴的是思路不是模型：置信度三档门控（高自动/中转人/低不动）在任何 AI 流程里都能用便宜大模型自己实现
  • 「列出业务里 LLM 只返回一个选项的调用」这个清单动作，今天就能做

前提与局限

  • 发布仅 4 天（2026-09-15），社区案例全是早期 demo，演示 ≠ 生产力（217 项目审计里今天真能用的仅 15 个）
  • 快 200 倍便宜 400 倍是厂商工作流自评上限且只对前沿模型成立；实际按「每解决一个任务的成本」算综合账
  • 「永不幻觉」要精确理解：不会答选项外的答案 ≠ 不会选错
  • 完全闭源只有云 API；仅文本不支持图像音视频；上下文仅约 32K
  • 数数算数日期归代码，无法提取未知值（先找候选再选），多步隐藏推理吃力
  • 需要文本生成时仍需大模型——两者是组合不是替代
