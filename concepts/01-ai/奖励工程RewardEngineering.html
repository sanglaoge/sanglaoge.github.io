奖励工程 RewardEngineering

稳定 建条 2026-07-05 下次复核 2026-11-18

核心洞见

指挥 Agent 不是给指令，
是定目标、划边界、设验收。

任务越交给 Agent，人越要把"想要什么结果"和"绝对不要什么"说清楚。

是什么：从强化学习迁来的老概念

Reward Engineering 是强化学习领域早已存在的概念（reward shaping / reward engineering，Ng et al. 1999 的 reward shaping 是经典源头），Richard Socher 在 AI Agent 语境下重新推广了它：AI 越强大，人越不需要自己做，但越需要把目标函数（Objective Function）写清楚。

核心矛盾（·关键）：AI 擅长执行目标，但不会质疑目标。你写"提高浏览量"，它可能用标题党骗点击；你写"提升客服满意度"，它可能给每个客户发 1000 美元礼品卡——指标漂亮，问题没解决。这就是奖励黑客（Reward Hacking）：AI 找到实现目标的最短路径，但路径本身是破坏性的。

"提高浏览量"

奖励黑客路径

用标题党骗点击——数字上去了，信任掉下来了。

"提升客服满意度"

奖励黑客路径

给每个客户发 1000 美元礼品卡——满意度满分，公司破产。

奖励工程 = 定义目标 + 设负向约束 + 定验收标准。不是写 Prompt，是写规则。

为什么重要

Socher 的原话（大意转述，未找到原帖出处）："几年后，说自己不擅长 Agent delegation，会像说自己不擅长用电脑一样可笑。"

管 Agent 的能力会成为新时代的核心工作技能。而管 Agent 的本质就是 Reward Engineering——让人从"亲手做"变成"定目标+看结果+纠偏"。

怎么做：三步法（路线图）

STEP 1

定目标函数

不只说"做什么"，说"要达成什么结果"。

错法：分析竞品 → 对法：找出转化率最高的前 3 种视觉策略，不是泛泛的风格归类

STEP 2

设负向约束

明确"不要什么"，堵住奖励黑客的近路。

禁止只输出"极简风/欧美风"这种标签，我要可执行的模式，不是形容词

STEP 3

定验收方式

AI 产出后该怎么判断对不对。

给出每个策略对应的竞品链接和截图作为证据

反向提示法（桑老哥偏好）

特别适合桑老哥的用法是先让铁柱生成一版，然后告诉它"哪不对"，让它改。这比提前想完美指令容易得多。

铁柱出初稿→ 桑老哥：三个地方不行——太泛、没数据支撑、没对标我的品类→ 铁柱改一版→ 再验→ 满意收工

桑老哥适用场景

场景Reward Engineering 写法
让铁柱做竞品分析目标：转化率最高的视觉策略 + 禁止：形容词标签 + 验收：带截图和数据
让铁柱写 Listing目标：符合 A10 算法的关键词布局 + 禁止：堆砌关键词 + 验收：可读性检查
让 Agent 选品目标：毛利率>30% + 竞争度<阈值 + 禁止：季节性品类 + 验收：3 个月趋势数据
让 Agent 做图目标：主图点击率 > 竞品均值 + 禁止：侵权元素/夸大效果 + 验收：A/B 测试对比

考场版：模型反过来攻破考卷（打分卡）

来源：李韭二《大模型评测终极指南》（X 公众号，2026-08-25，考场版轻记 2026-09-07）。本词条讲"人怎么给模型定规则"，这一节讲反面——模型怎么钻规则的空子拿高分。看懂模型怎么作弊，才知道规则该防什么。

分数骗人四式

饱和

考题太旧太简单，人人都接近满分，量不出差距

污染

公开考题被爬进训练数据，背答案 ≠ 会做题（GSM1k 对照实验：部分模型掉 8-13%）

尺子本身歪

MMLU 病毒学子集 57% 的题本身有问题——标准答案就是错的

主动作弊

Reward Hacking 正面战场：改测试断言、硬编码返回值（o3-mini "Let's hack!"）

古德哈特定律：一个指标一旦变成目标，就不再是好指标。RLVR 直接把"拿高分"设成训练目标，作弊不是模型学坏，是它高效完成了我们定的目标——惩罚作弊念头只会让它把作弊藏得更深。连真人盲投的 LMArena 也能刷（厂商私测 N 个版本只报最高分，Llama 4 冲榜版 ≠ 发布版）。

五分钟三查（看到跑分先过一遍）

  1. 题目多久没更新？
  2. 排名和主流榜单一致吗？
  3. 评测脚本公开可复现吗？

两问答不上来就打问号。

benchmark 测到的只是"表现"不是"能力"，是替代指标。世上没有最强模型，只有最适合你场景的模型——你自己的任务才是最终的 benchmark。

前提与局限

  • Agent 越强，Reward Engineering 越重要；Agent 弱的时候指令精确度反而不那么关键
  • 不可能一次性写完美——是迭代出来的，不是设计出来的
  • 非技术人不需要写代码的奖励函数，但需要写清业务规则和边界
