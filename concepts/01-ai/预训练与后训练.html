预训练与后训练

稳定 建条 2026-10-23 下次复核 2027-01-23

一句话说清楚

预训练负责让它知道，后训练负责让它会答——而"会答"教的只是说话的规矩和格式，不是新知识。

所以它能答得很像样，同时把事实说错得很自信。这不是它不用心，是这套流程从设计上就不管事实对不对。

理解这条，你就有了一个特别好用的解释器：AI 答得自信却答错事实，不是你问得不好。

来龙去脉：两篇连载，第二次撞见才升格

2026-10-21 与 10-23，东锡 NLP 连发后训练系列两篇：01 讲为什么需要后训练（base model 只会续写），02 讲后训练的第一种技术——指令微调（Instruction Tuning，也叫 SFT 监督微调）。

01 篇当时只在账本轻记了一行，明确留了句话："撞见续篇再议是否升格。"两天后续篇到了，按同概念第二次撞见升格建条。同一序列后续还有：偏好对齐、RLVR、LoRA/QLoRA。

这也是概念库的节制：第一眼是好东西，但只有它长成一条线，才值得占一个词条名额。

三段全景：先知道、再会答、最后答得好

第一段 · 预训练 pretraining

读海量原始文本，学"下一个词预测"

打比方：把图书馆读完，学会接着往下说

这一步之后，模型"什么都知道一点"，但不会当助手——你问它问题，它可能继续给你编问题。

成本量级：万亿级 token，三段里最贵

第二段 · 指令微调 SFT

喂成对的"指令 + 回答"，学按指令作答

打比方：教它"人家问你，你就答，别自己出题"

这一步之后，它像个助手了。但它只是学会了回答的形状，没有多学一分事实。

成本量级：几万到几百万条，三段里最便宜

第三段 · 偏好对齐 / RLVR

从"哪个更好""答案对不对"里学

打比方：请评审挑好坏 / 拿标准答案对错

这一步之后，它答得更讨人喜欢，也更容易答对难题。代价是会学会"看起来对"，校准开始变差。

成本量级：中等

铁律：预训练定"知道什么"，后训练定"怎么用"。后训练不换架构，只改性格。

三个实验，把"不增加知识"钉死

Alpaca

斯坦福 · 2023-03

52,000 条指令数据，8 块 GPU 跑 3 小时

Meta 的 LLaMA 7B 只做过预训练，没改结构，用不到 500 美元自动生成的数据、不到 100 美元的训练，就学会了按指令作答。但它连坦桑尼亚首都都答错——说达累斯萨拉姆，正确是多多马。

LIMA

2023

1,000 条精选示例，微调 65B LLaMA，不用强化学习

人工评测中 43% 的回答与 GPT-4 相当或更好。结论：知识几乎全部来自预训练，少量指令数据主要决定回答的方式。

FLAN

2021

20 / 25训练时没见过的任务上，超过零样本 175B GPT-3 的项数

把 60 多个 NLP 任务全部改写成自然语言指令，微调 137B 模型。说明学到的是"遵循指令"这项通用能力，能泛化。

示例教会了模型如何回答，但没有教会它哪些事实是正确的。 —— Alpaca 实验的结论

一条示例的三种形态

同一条训练数据，在流程里会以三种样子出现。看懂这三层，才看得懂训练日志。

形态长什么样
存储形态一段对话，每条消息标角色（system / user / assistant）
输入形态用对话模板（chat template）拼成一个 token 序列，插入特殊标记（Qwen 用 <|im_start|> 角色名 开头、<|im_end|> 结尾）
训练形态用损失掩码（loss mask）标出哪些 token 参与算损失

哪些 token 算损失（判断标准只有一条）

只对模型在实际使用时需要生成的那部分算损失。

算损失

  • 回答主体——它真正要说的内容
  • 结尾的 <|im_end|>——不教这个，模型答完不会停，甚至替你编下一句提问

不算损失

  • 用户消息——算的话模型会学成"自己提问"
  • <|im_start|>assistant 开头标记——实际使用由程序写入
  • <|im_end|> 之后的换行

两个技术坑：

  1. 被掩码 ≠ 不学。掩码只决定"哪些位置的预测计分"，不影响注意力读取。回答的损失产生的梯度会通过注意力传回提示词，照样更新参数。不考核，但照学。
  2. 必须错开一位：cross_entropy(logits[:-1], labels[1:], ignore_index=-100)。没错开也能跑、形状还对，但学的是"复制当前 token"。训练前把参与损失的 token 解码出来看一眼，应当只剩回答和各条 <|im_end|>。

数据从哪来 + 一个容易忽略的偏斜

三个来源：人工编写（质量高、成本高）／改写现有数据集（模板套翻译、问答、情感分析）／模型生成（目前最常用，需筛选审核）。

数据质量杠杆很硬：在大型指令数据集里加 500 条安全示例，模型产生有害回答的比例就明显下降。

长度偏斜：损失按 token 平均，一条 500 token 的回答，权重约是 2 token 回答的 250 倍。配数据要按 token 总量平衡，只看条数会严重偏斜。

SFT 能做到与做不到

能做到

  • 低成本学会按指令作答
  • 遵循格式（列表 / 单词 / 译文）
  • 区分多轮对话角色
  • 适时停止
  • 拒绝某些请求
  • 泛化到训练时没见过的任务

做不到

  • 可靠地补充知识（Alpaca 答错首都）。还可能学会"没把握也照样肯定地答"
  • 超越训练数据：模仿示例，也模仿示例里的错误
  • 比较优劣或判断对错：每条示例只有一个参考回答，它没法知道两个都合理的回答哪个更好，也没法判断一长串解题过程最后对不对

这三条正是后续技术的分工：偏好对齐从"回答之间的比较"里学；RLVR 从"答案对不对"里学。推理模型的训练也走这个顺序：先用写好的解题过程做 SFT 学推理格式，再用强化学习提高正确率。

错法 → 对法

错法对法
以为"喂更多知识"就能改行为行为靠成对示例教（要知识得靠预训练或检索），要它少犯事实错误得靠 RLVR 和外部信源
以为"数据条数够了"按 token 总量看权重，长回答会吃掉整锅权重
以为掩码的部分没在训练掩码只管计分，注意力照读，梯度照回传
训练完只看 loss 下降要拿到"训练时没出现过的任务"上测（FLAN 的做法），否则只是背了格式
以为 SFT 完就能判对错判对错要靠 verifier / 偏好数据，SFT 只能模仿

前提与局限

  • 三个实验都是 2021—2023 年的论文数字，现在数据规模与配方都不同，别当今天的性能基准，只当机制证据。
  • "43% 与 GPT-4 相当"是人工评测、口径见原论文，属于当年的对比。
  • 本文讲的是指令微调这一种后训练技术，不等于全部后训练；偏好对齐、RLVR、LoRA 各有一篇。看到"后训练"三个字别等同于"SFT"。

桑老哥适用场景

  1. 讲 AI 科普时最好用的一句：AI 答得自信却答错事实，不是你问得不好——它学的是怎么答，不是事实对不对。这句能直接当视频开头钩子。
  2. 写提示词时的启示：想要格式听话（列表、字数、语气）→ 指令写得越清楚越有效；想要事实准确 → 靠喂材料（上下文工程）+ 让它核对，别指望语气。
  3. 看懂模型发布时的名词：厂商说"instruction tuned / chat model"就是在 base model 上做了这一步；说"RLHF / DPO / RLVR"是在后训练的更后面几步。
