AI底层逻辑 · 回答 ≠ 负责

可信完成

稳定 建条 2026-07-29 更新 2026-11-02 下次复核 2026-11-18

核心洞见

Agent 不缺代码，缺可信完成。一次回答可以失败重问，一次真实动作不能盲目重试。

是什么：标准变了

当 AI 从「只回答问题」升级到「能动手干活」（写文件、跑命令、发邮件、花钱、改数据），衡量它的标准变了——从「推理质量」变成「可信完成」。八个问题先立起来：它以谁的身份在行动？只能触达什么？环境是否可复现？中断后能否恢复？结果如何验证？副作用如何审计？人类何时能接管？「完成」到底由谁认定？

核心结构：Agent ＝ 概率性推理核心＋确定性执行外壳
要点：外壳五道护栏管住会猜的核心——身份、幂等、预算、接管、证据

为什么重要：回答 ≠ 负责

一次回答

失败了重问，零成本。衡量它看「推理质量」就行。

一次真实动作

做一半崩了，盲目「重试」会重复扣款、重复发邮件——衡量它必须看「可信完成」。

所以靠谱的 Agent 必须有五件套：动作身份（哪个任务第几步）、幂等键（同一动作做两次效果等于一次）、超时与预算上限、人工接管口子、以可核验的证据驱动完成判定。

终点不是「最大自治」，而是让一个不完全可靠的推理者，在可靠系统里持续承担责任。

怎么用：四个问题（验收打分卡）

1

它做了什么？

动作清单，不是「干完了」三个字。

2

依据是什么？

每一步的来源与理由，可追溯。

3

结果是否成立？

怎么验：截图/数据/测试，不是自述。

4

失败后如何恢复？

重试会不会重复扣款？回滚路在哪？

落到操作：派活前定 Goal（结果＋约束＋验收）；干完不靠它自述，靠证据（截图/数据/测试）验收；高风险动作（花钱/发邮件/改生产）必须留人工接管口子。

越是「有副作用」的任务越要用这套（花钱、对外发送）；纯生成（写文案、出图）风险低，可简化。简单问答用不上——杀鸡用牛刀。

前提与局限

  • 简单问答用不上这套（杀鸡用牛刀）
  • 这是工业级 Agent 设计原则，你是使用者不是开发者——吸收「四个问题」做验收即可，不用懂实现
  • 越是「有副作用」的任务（花钱、对外发送）越要用这套；纯生成风险低，可简化

放行机制：自主权按操作逐项赢得

前面几节讲「完成由谁认定」，这一节讲放行权怎么分配、什么时候能收回人工那一票。来源：Yarchi《How to Build a Production AI Agent: The 7 Layers Between the Model and the Result》（X 2026-10-30，WaytoAGI 转载；赞助内容），对应七层栈第 6、7 层。

风险三级，一级一条规矩

级别判断规矩
低只生成内容 / 计划 / 草稿，可一键撤回自主跑，留痕
中有外部影响但可逆跑，但必须留痕可查
高涉及资金 / 不可逆 / 对外发送等人工批准

派活前先过三个自测问题：要不要产出内容 / 计划 / 草稿？涉不涉及钱？能不能一键撤回？

核心规矩：自主权按「单个操作」逐项赢得

不是按「整个智能体」一次性放权，而是按「一个操作」逐个放权——赢来的，才给。

降级条件写死：只有几十次批准、且一次都没被修改过，才把一个操作从「等批准」降到「自主跑」。作者自己的永久白名单只有四项——发邮件、删除、发布、买东西，前面草稿再完美也不跳过。

致命三重奏：最快的泄露自测

私有数据

它能看到不该外流的东西。

不可信内容

网页、邮件、用户输入都可能藏指令。

对外通信能力

能把内容发出去。

三者凑齐 ＝ 数据泄露风险（Simon Willison，2025-06）：必须人工把关；缺一条，风险量级完全不同。与 MCP-Skill-Hook 三件套的四级安全分级同向。

警示案例：指令是愿望，权限边界才是护栏

2025-07，一个 Replit 智能体在「代码冻结」期间删掉了 SaaStr 创始人 Jason Lemkin 的生产数据库，事后自称「慌了」。解法不是更好的提示词，而是开发 / 生产分离、一键恢复、只读密钥。

写在提示词里的规矩只是愿望；能拦住动作的权限边界才叫护栏。

落地清单（桑老哥版）

  • 沙箱先行：测试库、测试账号、只读密钥，永不用管理员账号
  • 每个工具标风险级别，高风险工具默认「等批准」
  • 记录谁批准了什么（批准人 + 动作 + 范围 + 有效期）
  • 每月只降级一个操作，且要有「几十次未修改」作证据

桑老哥适用场景

场景怎么用四问
AI 自动发邮件/发飞书/推商品上架必须有预算上限＋人工二次确认（防重复、防乱发）
AI 跑选品数据/分析完成判定靠数据交叉验证，不靠它说「分析完了」
用铁柱（Agent）跑长任务要求证据链（截图/日志/diff），不是只给结论

实测：Personal Agent 在中国大陆能办完什么事（2026-10-30 并入）

来源：钱西瓜《Personal Agent 在中国大陆能办完什么事？》（X 2026-10-27，WaytoAGI 转载）。这是本词条八个问题的第一份中国大陆实测——不讲原则，是拿四款产品真去订酒店、买火车票、打车、买咖啡，看它们在哪一步停下。产品版本 2026-10-20：Grok Bot（xAI）· Muse（Meta）· Dots（OpenAI）· Instinct（邀请制）。

测法可直接复用：8 个通用任务，同一套提示词，明确允许在「登录 / 短信验证码 / 付款」三处人工接管，记三样——完成情况、耗时、接管次数，外加卡在哪一步。

完成度与代价

产品完成度实测代价（关键场景）
Grok Bot7/8订酒店 10:08、接管 3 次；唯一走通买咖啡与打车
Muse5/8订酒店 15:15、接管 3 次；过程最可看（有任务面板）
Instinct4/8订酒店 26:34、接管 8 次，首推酒店还超预算
Dots1/8只跑通行情监控；多场景 15 分钟以上无响应
只能看三个数：完成没 · 多久 · 接管几次。10 分钟接管 3 次还能忍，26 分钟 8 次等于自己动手。

四道墙：所有产品倒在同一处

登录 → 短信验证码 → 付款 → 复杂网页提单。12306 是标本：三家都能查到票，全员走不到下单，卡在短信验证登录与提单校验。一句话——检索和规划都能做，一到「要证明你是谁、要花你的钱」就停。

最硬一条结论：接 MCP 的赢，走网页的输

Grok Bot · 走接口

主动找到瑞幸 MCP、滴滴 MCP → 下单、叫车全通。

Muse · 点网页

找到美团 / 饿了么 / 高德网页端 → 卡登录，连打车入口都找不到。

含义

同一件事，走接口通、点网页卡死。MCP 不是高级功能，是跨过网页墙的唯一现实通道。副产物：瑞幸、滴滴已有 MCP 服务。

自带邮箱 = 代理身份

Grok Bot 给每个用户开 @mail.grokbot.com 邮箱，注册和收验证码都用它，不借本人邮箱。这直接回答本词条第一问「它以谁的身份在行动」：给它专用身份，验证码这道墙倒一半，付款那道还在。

边界五条：n=1（每场景只跑一次）· 全在 beta（三个月内可能反转）· 自评分数（无评分细则、未披露利益关系）· 地区门槛（Muse 仅限美国 18+、Instinct 不支持 +86、Dots 需付费套餐、Grok $30/月起）· 不可复制（Grok 打车靠滴滴 MCP 已存在）。四款都不是大陆可用主力。
