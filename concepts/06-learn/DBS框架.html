DBS框架

稳定 建条 2026-08-03 下次复核 2026-11-18

核心洞见

知识不是一堆平等的清单，而是三种不同形态的东西：方向（怎么做）、蓝图（参考什么）、脚本（自动执行什么）。分清这三类，知识才能真正用起来。 来源：hooeem《4 Workflows to integrate Claude Code with NotebookLM》

三个桶

桶英文内容在 AI Skill 中在知识整理中
D - 方向Direction核心逻辑、决策树、步骤流程、错误恢复SKILL.md 的核心这个领域的核心流程是什么？
B - 蓝图Blueprints静态参考：模板、语气指南、分类规则支撑文档有哪些模板和案例可以参考？
S - 脚本Scripts确定性代码任务：API 调用、数据格式化打包脚本哪些步骤可以让 AI 自动执行？

判断路线图 ·核心

拿到一份新知识，别急着记，先顺着路线问三个问题，落进对应的桶：

用法：一条知识可能同时占多个桶（流程进 D、配着的模板进 B、能自动跑的步骤抽成 S），但先问 D——没有方向，蓝图和脚本都没处挂。

为什么有用

D = 思考

需要 AI「思考」的部分（核心）

核心逻辑、决策树、错误恢复。这是知识的深度所在，值得反复打磨。

B = 参考

需要 AI「参考」的部分（支撑）

模板、语气指南、分类规则。静态即可，用的时候翻出来照着对。

S = 执行

不需要 AI 思考，直接执行（自动化）

API 调用、数据格式化这类确定性任务，写成脚本一次搞定。

这种拆法让知识组织既有深度（D）又有广度（B），还能自动化（S）。

打分卡：拿「AI 选品」练手

学任何新领域，按 DBS 三个桶整理笔记

以 AI 选品为例，三问过一遍，笔记自动归位：

D 问AI 选品的核心流程是什么？——决策树、选品闸门、错误恢复，写进核心文档
B 问选品调研报告的模板、常用分析框架——存成支撑文档，用的时候翻
S 问哪些调研步骤可以让铁柱/爱马仕自动跑？——抽成脚本，一键执行
