DESIGN.md：给 AI 的视觉角色卡

草稿·待验证 建条 2026-08-03 下次复核 2026-11-18
本条为半成品概念（源词条 verified: false）——思路可用，具体工具与流程待实测验证，复习时请留意。

一句话本质

DESIGN.md 不是 token 文件，也不是灵感网站，而是给 AI 的一份「视觉人格说明书」——告诉它产品长什么样、为什么这样、什么永远不能乱来。

故事的起因：一股「默认模板味」

紫蓝渐变打底
大圆角卡片随手摆
按钮位置像猜的
字体间距没有章法
诊断：不是模型不会设计，是它没有稳定的设计上下文。你说「像 Linear 一样干净」对设计师够用，对 AI 太软——它只会输出训练数据的平均值。

它长什么样：两层结构

机器读
YAML front matter
颜色、字体、间距、圆角、组件属性
传统 token 只做到这一层：告诉 AI「有什么值」
人/AI 都读
Markdown body
品牌气质、颜色怎么用、组件不要怎么做
DESIGN.md 的增量：告诉 AI「为什么和什么时候用」

进入团队：三份文件配齐

AGENTS.md
工程协作：怎么跑项目、改代码、测试
SKILL.md
专业工作流：遇到某类任务怎么做
DESIGN.md
视觉人格：产品长什么样，什么不能乱来

三层齐全，AI 才不会每次开新会话都重新发明一套界面。

6 个工具怎么选（四梯队）

梯队工具适用场景
第一梯队Refero Styles先找方向，帮 AI 建立「见过好设计」的前置经验
第二梯队designmd.supply / DesignMD.me已有目标网站，快速生成可执行规范
第三梯队design-md-chrome浏览器随时抓，不打断工作流
第四梯队Neuform / getdesign.mdprompt 直接出页面 / 品牌灵感对照

首选 Refero 的原因：打开一个风格就能拿到 5 层资产——Preview（看整体气质）、DESIGN.md（给 agent 的说明书）、CSS Variables / Tailwind v4（接入主题层）、Components（按组件级规则生成）、Do/Dont（验收清单）。

四步闭环：说明书是养出来的

1 · 选方向
Refero 选 1 个主风格 + 1-2 个辅助（一个主方向就够，别贪多）
2 · 生成
designmd 抓目标网站 → 生成 DESIGN.md
3 · 上岗
放项目根目录 → 让 AI 读 + 复述原则 + 写代码
4 · 回写变厚
截图自审 → 把新规则回写 DESIGN.md——它是产品的视觉记忆，随项目迭代持续沉淀，不是一次性下载文件

避坑：六条不要

  1. 不要复制大品牌外观——借的是规则不是皮肤
  2. 不要当万能药——它只提高起点，仍需截图验收和人工判断
  3. 不要只写 token——没有设计理由，AI 还是会乱用
  4. 不要一次塞太多风格——一个主方向 + 两个辅助就够
  5. 不要忘记移动端——写明断点、触控尺寸、信息密度
  6. 不要长期不更新——每次沉淀新组件都应回写

给 coding agent 的提示词模板

你是资深前端设计工程师。请基于这个 Refero Styles 页面
[粘贴链接] 里的 DESIGN.md、CSS Variables、Tailwind v4 和
Design Tokens，为我的[产品/页面]生成一版可运行页面。

开始写代码前先做三件事：
1. 读取 DESIGN.md 和 tokens
2. 输出 5 条不可违反的视觉原则
3. 给出页面结构草案

实现时必须把 tokens 接入主题层，组件样式优先使用 tokens。
请从当前 Refero 页面提取主 CTA 颜色、卡片处理方式、圆角、
字号、间距和按钮高度等规则。

交付时请列出修改文件，并按颜色、字体、间距、圆角、卡片、
CTA、图片使用逐项自查。

铁柱注解 · 桑老哥适用

对桑老哥的实际价值

做跨境电商图片/视频，AI 出图时如果带上 DESIGN.md，「模板味」问题能直接缓解。入手顺序：先用 Refero 找 2-3 个喜欢的风格 → 把设计说明放进自己的提示词库 → 后续生图/做页面都带它。

上位概念

AI角色设定集——「一份角色文档约束所有输出」的人设层版本，本条是它的视觉层特化。配合 海报构图16式（单张骨架）与 生图提示词排查表（交付质检）三层各管一段。
