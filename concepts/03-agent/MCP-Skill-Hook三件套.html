MCP-Skill-Hook三件套

稳定 建条 2026-07-27 下次复核 2026-11-18

一句话说清楚

Agent 三件套 = MCP 给能力（手） + Skill 定流程（脑） + Hook 管底线（闸）。

分工：MCP 解决「能干啥」，Skill 解决「按啥顺序干」，Hook 解决「被允许咋干」。打个比方——把 AI 当新来的实习生：MCP 是双手（没手只能动嘴），Skill 是脑子里的操作手册（先做啥再做啥），Hook 是安检门（每次伸手前过一道闸）。

三件套各管什么 ·核心

手

MCP

能操作什么

解决
接外部能力：数据库、搜索、API
铁柱里的对应
sorftime / tavily-search / lark-cli
脑

Skill

怎么正确操作

解决
编排顺序：先做啥再做啥
铁柱里的对应
PAI / frontend-design / luban 等 27 个
闸

Hook

被允许怎么操作

解决
安全边界：拦危险动作
铁柱里的对应
CLAUDE.md 的「别直接删」「高风险先问」「口播句强制」

MCP 三种原语（控制权是核心轴）

原语控制权加载方式适合场景
Tools 模型控制（Model-controlled） 客户端启动时注册，供模型按需调用（「注入 system prompt」只是部分客户端的实现细节，非规范） CRUD、部署、启停等「动手」操作（唯一能改外部状态）
Resources 应用控制（Application-controlled） 惰性按需拉取 表 schema、数据字典等大量结构化参考（不占 prompt）
Prompts 用户控制（User-controlled） 惰性按需获取 标准化引导的重复性任务

四级安全分级：最该抄的作业 ·核心

Hook 不是二元「允许/拒绝」，是渐进式四级：

一级
静默放行

纯查询，不打扰

二级
审计记录

低风险写操作（存草稿），悄悄记一笔账

三级
弹窗确认

高风险写操作（发布上线），必须用户点头

四级
硬阻断

不可逆删除（删数据库），直接拦死

风险越高 → 闸越硬：从「不打扰」到「拦死」

全篇金句：软嘴 vs 硬闸

prompt 约束是软的

  • CLAUDE.md 里写一百条「不要 X」
  • AI 一「自信」就绕过
  • 靠嘴保证，没有强制力
对撞

Hook 是硬的

  • 工具调用链路上 AI 绕不开的道闸
  • 写进程序，不靠模型自觉
  • 管 AI 得靠硬闸，不靠嘴
安全边界不靠 prompt 保证，靠工程架构保障。

轻记：WebMCP（2026-08-31 并入）

Chrome 和 Edge 团队在做同一个浏览器 API：让网站把能做的操作写成清单（名称 + 给模型读的描述 + 输入类型），智能体照单调用——声明胜过猜测（Akshay 科普，2026-08-29，附官方文档）。

智能体到达应用的六种方式：原始 API / 后端 MCP 服务器 / 计算机使用（截图点击）/ 浏览器自动化 / WebMCP / 站内助手——WebMCP 是唯一「自己的智能体 + 零配置 + 真命名操作」三者全留。

  • 登录白送：在用户已登录的会话里跑，不用 API 密钥
  • 不会误点：拿到清单不是猜按钮
  • 网站改版不失灵：菜单网站自己维护

给商家的启示：未来「把能做什么写清楚」的网站拿到更可靠的 AI 流量——与详情页写明卖点同理，这次的读者是 AI。MCP 生态从「工具方搭服务器」走向「网页自我声明」。

前提与局限

  • Hook 不是万能：规则写太严，AI 会「动弹不得」，啥都问人，效率反降。软（prompt）和硬（hook）要配合，不是全押硬的
  • tier 条件链、SA-Market、symlink、Agent Plugin Factory 等工程实现细节，是程序员搭 MCP Server 才用的，桑老哥不写代码可跳过
  • WebMCP 还是进行中的浏览器提案，落地节奏看 Chrome/Edge 官方进度

桑老哥适用场景

  • 铁柱本身就是这三件套搭的。理解底层逻辑后，优化自己的系统有方向：把 CLAUDE.md 里的「软嘴」（不要 X）逐步升级成 Hook 的「硬闸」（绕不开的强制检查）
  • 配置类高风险操作（删文件/推代码/花钱）值得做成 Hook 三级（弹窗确认）或四级（硬阻断），而不是只写在 prompt 里
