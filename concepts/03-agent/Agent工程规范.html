Agent自动化 · 把 Agent 从「能演示」做到「能上线」

Agent工程规范

稳定 建条 2026-09-04 下次复核 2026-12-04

一句话说清楚

模型负责动脑，程序负责刹车——别让一段文字干代码的活。

这是把 Agent 从「能演示」做到「能上线」的工程总纲：什么活该交给 Agent、怎么派活、怎么保证停得下来、怎么验收，四件事一套说清。

本条 · 规范层

工程上怎么派活、怎么刹车、怎么验收——把单点词条串成一套

Agent 公式：六件套

Agent = 模型 + 目标 + 工具 + 记忆 + 运行循环 + 安全边界 大脑 + 知道啥叫干完 + 手脚 + 记性 + 干活节奏 + 围栏
模型大脑

负责推理与决策

目标知道啥叫干完

没有目标就没有「完成」

工具手脚

搜索、数据库、API 等外部能力

记忆记性

跨步骤、跨会话带上前情

运行循环干活节奏

思考→行动→观察→再思考

安全边界最常被漏

直接决定能不能上线。没围栏的 Agent，像揣着钥匙、全靠猜决定下一步的临时工

先问四句，再决定要不要用 Agent ·核心

一问

这活是不是要走好几步判断？

二问

中途拿到的新信息，会不会改变下一步？

三问

是不是得动用外部工具（搜索/数据库/API）？

四问生死问

结果能不能被检查？干错了能不能拦住或撤回？

前三条大多是「是」、第四条有办法，才值得做 Agent。第四条无解——自动化程度越高，风险越大。

对照记住：固定报表这种路线清楚、输入稳定的活，普通脚本更省钱更稳。Agent 不是高级，是另一种工具。

循环的灵魂是停得下来：三道闸

演示里的循环是圆圈：思考→行动→观察→再思考。工程里必须加三道闸：

步数上限

防来回打转、不停换关键词重试

时间上限

防某步卡死，到点及时撤

费用上限

Token、搜索次数、API 费用封顶

停止不是失败。能在失控前刹车、把已完成的部分交给人，才是可用系统。 —— 与 Prompt三原则 的 TERMINATION 同源：早点停 = 省钱 + 保命

全文最值钱：任务合同 ·核心

别只说「帮我研究一下」。先写一份合同，三段：

输入给什么
  • 研究主题
  • 目标读者
  • 截止日期
输出要什么
  • 800-1200 字简报
  • 5 条结论
  • 每条事实带可访问链接
停止条件何时收工
  • 找到 3 个独立来源
  • 最多搜 12 次
  • 最长跑 8 分钟

一人分饰三角：给 AI 看是提示词，给你看是验收表，给钱包看是预算表。

最重要的推论：结果不好，先查合同哪里写含糊了，别急着换模型。

六大误区：直觉 vs 实情

工具越多越强？

直觉工具箱越满能力越强
实情工具越多越挑花眼，按阶段加载比一次全塞强

提示词越长控制越准？

直觉规矩写得越多越听话
实情规则打架时长度只会放大混乱；权限和校验写进程序，别指望一段文字

多 Agent 天然胜过单 Agent？

直觉人多力量大
实情每多一层协作就多一层延迟、费用和信息损耗

RAG 能消灭幻觉？

直觉给了材料就不会胡说
实情RAG 只管找材料，找错切错照样胡说，引用核验不能省

能跑通一次就算成功？

直觉演示通过=能上线
实情演示都避开了登录失败、限流、脏数据

Agent 应该完全自主？

直觉越自主越先进
实情自主程度由风险决定：查资料自动、发邮件出草稿、转账必须人点头（= 桑老哥家红黄绿灯的翻版）

桑老哥直用

  • 派活模板：给铁柱/爱马仕派任务时套任务合同三段——尤其「停止条件」和「输出格式」两段
  • 判断该不该自动化：四问里第四问（错了能不能拦/撤回）过不了就保持人工
  • 自主程度分级直接对齐红黄绿灯：绿 = 自动干、黄 = 干完汇报、红 = 等人点头

前提与局限

  • 本条是工程总纲不是代码教程——落地时每个闸（步数/时间/费用）要按具体活定数值
  • 「程序负责刹车」的前提是你有一个能执行程序的环境（Harness 层），纯聊天窗口里做不到
  • 任务合同防的是「含糊」，防不了「目标本身定错」——目标对不对仍要人判断
