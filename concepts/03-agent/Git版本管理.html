Git版本管理

稳定 建条 2026-08-18 下次复核 2026-11-18

一句话说清楚

Git 是存档系统：没存档的改动丢了就丢了。对 AI 的产出，diff 白纸黑字才算证据，嘴上说「做完了」不算。

搬家公司的四站旅程

把改文件想成搬家：东西从房间出发，一站一站往前送，每过一站就多一层保障。

第一站

工作区房间里的东西

你正在改的文件。Cmd+S 只是写硬盘，Git 还没记录——东西还在房间里，随时可能丢。

命令：还没有，这只是起点
第二站

暂存区装上货车

git add 文件 挑着装车。上了车还能卸下来——这一站可以反悔。

命令：git add 文件
第三站

本地仓库签收，拍板定死

git commit -m "说明" 盖章存档。从这一站起，历史里有据可查。

命令：git commit -m "说明"
第四站 · 终点

远程仓库发车去云端

git push 异地备份。本地硬盘坏了，云端还有一份。

命令：git push

翻译坑：三个词的故事

中文直译最容易把人带沟里，桑老哥共学时踩过：

add 不是「增加」，是「列清单」

把要搬的东西列上装箱单，东西本身没动。

2026-08-18 桑老哥踩过
commit 不是「提交」，是「盖章存档」

中文「提交」误导人——它跟「交出去」无关，交出去是下一站的事。

2026-08-18 桑老哥踩过
push 才是「交出去」

本地仓库发车去云端，从这一步起别人才看得到。

2026-08-18 桑老哥踩过

分支 = 复印底稿

拿不准的改动在复印件上试：满意合并（merge），砸了扔掉，主干无损

冲突：主干和复印件改了同一行，Git 不敢替你选，把两版摆出来你拍板。只一边改，不冲突。

三连查口诀

status 看位置 / diff 看内容 / log 看历史

git status

状态：改动在哪一站——房间、车上、还是已签收

git diff

差异：绿行新增、红行删除，内容级证据

git log --oneline

日志：签收单列表（feat 新功能 / fix 修 bug / chore 杂务）

Git 是 AI 的验收系统 ·核心

错法

  • AI 说「完成了」
  • → 直接用

对法

  1. AI 说「完成了」
  2. → diff 看改动
  3. → 实测
  4. → 才 commit 签收

与可信完成同源：铁柱说做完了不算，看真实信号；diff 就是那个信号的技术底座。

边界

  • 本词条覆盖日常 90%（存档 + 试错 + 排查）；rebase、revert、submodule 等进阶操作用到再学
  • GitHub ≠ Git：Git 是本地工具，断网可用；GitHub 是云端仓库网站
  • diff 证明「改了什么」，不证明「改得对不对」——对不对要靠实测
